# 30 — Workflow

## Цикл задачи
1. Прочитать релевантные файлы и доки; ничего не менять.
2. Дать план ≤ 10 шагов и список файлов с полными путями.
3. Остановиться и ждать «go». Без «go» — ни одной записи на диск.
4. Один шаг = один файл или одна атомарная правка; темы не смешивать.
5. Запустить `flutter analyze` и `flutter test`. Падение — стоп, чинить в рамках шага.
6. Обновить CHANGELOG.md; архитектурное решение — в DECISIONS.md.
7. Отчёт: что сделано, что не сделано, риски, следующий шаг.

## Отчёт
- Что изменено: пути файлов и суть.
- Проверка: вывод analyze/test, что именно проверено.
- Неоднозначности: где пришлось выбирать и что предлагаешь.
- Следующий шаг: одно предложение.

## Definition of Done
- `flutter analyze` — ноль issues, ноль подавлений.
- `flutter test` — зелёный; domain покрыт ≥ 80%.
- Нет TODO/FIXME без записи в BACKLOG.md.
- Нет отладочного вывода, секретов, мёртвого кода.
- Изменение откатывается одним revert, без ручных доводок.
- Документация обновлена в том же шаге.

## Коммиты и границы
- Один коммит = одна задача из BACKLOG.md; сообщение в императиве.
- Замеченный долг вне scope — запись в BACKLOG.md, не правка.
- Не менять чужие файлы «заодно»; не переписывать файл целиком, если хватает точечной правки.

## Стоп-сигналы
- Нужна новая зависимость → ADR, потом «go».
- Нужна разрушительная операция → отдельное явное подтверждение.
- Неясна сигнатура API → проверка по docs/pub.dev, не по памяти.
