# 20 — Code Style

## База
- Линтер: very_good_analysis, без ослаблений. Исключение — только с обоснованием и записью в DECISIONS.md.
- Форматирование: dart format, один стиль на весь репозиторий.
- Импорты только используемые, порядок задаёт линтер.

## Обязательно
- freezed для state, событий и value objects. Ручные ==/hashCode/copyWith не пишем.
- dartdoc для всего public API пакетов и domain-контрактов.
- Имена по смыслу: без сокращений, без венгерской нотации, без «manager»/«helper»/«util» без нужды.
- Ошибки — через явные типы (sealed-иерархии или Result), не через null в неоднозначных случаях.
- Тесты domain ≥ 80% строк: каждый use case, граничные случаи SM-2, логика UTC и TZ.

## Запрещено
- dynamic и неявные касты; тип выводим из сигнатуры.
- print и debugPrint в коде приложения — только логгер с уровнями.
- Мутабельные глобалы и сервисы-синглтоны вне DI.
- Логика в виджетах: расчёты в domain, виджет только отображает.
- Магические числа и строки — только именованные константы.
- Комментарии «что делает код»; только «почему», если это неочевидно.

## Тесты
- Имена: should_<expected>_when_<condition>.
- Один assert-намерение на тест; фикстуры явные, без скрытых мутаций.
- Никаких сетевых вызовов и системного времени: часы и зависимости внедряются.

## Документация
- Публичное поведение описывается в dartdoc, а не только в отчёте.
- Изменение контракта — запись в CHANGELOG.md; архитектурное решение — ADR.
